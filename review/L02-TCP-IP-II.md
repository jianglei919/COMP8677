## 一句话概览
传输层做**进程到进程**通信（TCP 可靠 / UDP 尽力而为 + 多路复用分解 + 流量控制）；网络层做**主机到主机**的路由转发（IP 数据报、分片、IP 编址、子网、DHCP）。

## 二、传输层

### 1. TCP vs UDP（★必背对比★）
| 特性 | **TCP** | **UDP** |
|---|---|---|
| 连接 | 面向连接（需3次握手建立） | 无连接（no handshaking） |
| 可靠性 | 可靠、按序字节流 | 不可靠、可能丢失/乱序 |
| 边界 | **无报文边界**（字节流） | 保留报文边界（独立处理每个段） |
| 流量控制 | ✅ 有 | ❌ 无 |
| 拥塞控制 | ✅ 有 | ❌ 无 |
| 其他 | 流水线、设置窗口大小 | "无修饰 no-frills"、尽力而为 best-effort |

- **两者都不提供**：延迟保证（delay guarantee）、带宽保证（bandwidth guarantee）。
- UDP 是"IP 的轻量扩展（no-frills extension）"，适合 DNS、流媒体、游戏等。

### 2. 多路复用 / 多路分解（Multiplexing / Demultiplexing）★高频考点★
- **定义**：每个应用有自己的 **socket** 和**收发缓冲区**。
  - **多路复用（发送端）**：从各应用缓冲区取数据 + 加头部 → 发出。
  - **多路分解（接收端）**：去头部 → 把报文放到**正确的接收缓冲区/socket**。
- **关键区别**：
  - **UDP 分解**：仅靠 **目的端口号（dest port）** 定位 socket。
    - ⭐ **样题4**：UDP 多路分解需要的信息 = **只需目的端口（only dest port）**。
    - （UDP socket 概念上由 2 元组 *(目的IP, 目的端口)* 标识；在同一主机上**区分 socket 靠目的端口**。）
  - **TCP 分解**：靠 **4 元组**：*(源IP, 源端口, 目的IP, 目的端口)*。
    - 所以同一服务器端口可同时服务多个客户端连接（每个连接一个不同的 4 元组 socket）。

### 3. UDP 校验和（Checksum）
- **目的**：检测段在传输中是否出错（如比特翻转 flipped bits）。**只能检错，不能纠错。**
- **算法**：发送方把段内容（含头部字段）看成一串 **16-bit 整数**，做**反码求和（one's complement sum）**，结果放入 checksum 字段；接收方重新计算并比对。
- **检错 vs 纠错的类比**：你能轻易验证别人的解答是错的，但不一定知道怎么改对它。

### 4. TCP 可靠传输 + 连接建立
- TCP 特性：**点到点**、**可靠按序字节流**、**无报文边界**、流水线、拥塞+流量控制、设置窗口大小。
- **三次握手（3-way handshake）**：
  ```
  客户端 → SYN,    seq=x              （想连接）
  服务器 → SYN+ACK,seq=y, ack=x+1     （同意）
  客户端 → ACK,    seq=x+1, ack=y+1   （确认）
  ```
  - ⭐ **样题5**：SYN 包 seq=123，同一发送方回复 SYNACK 的那个 ACK 包 seq = **124**（即 x+1，序列号 +1）。
  - 关键规则：SYN/FIN **各消耗 1 个序列号**。

### 5. 流量控制（Flow Control）★高频★
- **场景**：当一个分组到达 IP 层 → 去 IP 头得到 TCP 段 → 传输层去 TCP 头 → 应用数据放进 **socket 接收缓冲区**；应用调用 `recv()` 等从缓冲区读走数据。
- **问题**：若应用**读取速度 < 数据到达速度**，接收缓冲区会**溢出（overflow）**。
- **解决**：**流量控制**——让接收方控制发送方，使其不会因发太多太快而**溢出接收方缓冲区**。
- **机制**：接收方在回复包的 **TCP 头部 `receive_window`（接收窗口）字段**告诉发送方"还能收多少"，发送方据此放慢/限制发送量。
- 💡 一句话：**流量控制 = 接收方对发送方的限速（防接收缓冲区溢出）**；区别于**拥塞控制 = 防网络拥塞**。

## 三、网络层

### 6. 转发 vs 路由（Forwarding vs Routing）★易混必考★
| | **转发 Forwarding** | **路由 Routing** |
|---|---|---|
| 含义 | 把分组从路由器**输入端口**移到合适的**输出端口** | 决定分组从源到目的所走的**路径** |
| 范围 | 本地、单个路由器内部动作 | 全局、跨多个路由器 |
| 时间尺度 | 纳秒级（每个分组） | 较慢（路由算法运行） |
| 类比 | 走到某个路口该往哪拐 | 规划整条路线 |

### 7. 路由器结构
- **第一代路由器**：传统计算机，交换在 **CPU 直接控制**下进行，分组被**复制到系统内存**（慢，成为瓶颈）。

### 8. IP 分片（Fragmentation）
- 每种链路有 **MTU（最大传输单元 max transfer size）**，不同链路类型 MTU 不同。
- 大的 IP 数据报会被**分片（fragmented）**成多个数据报，**只在最终目的地重组（reassembled）**。
- IP 头部字段（**identification, flags, fragment offset**）用于**标识和排序**相关分片。

### 9. IP 编址与子网（Subnet）★最高频考点★
- **IP 地址 = 32 位**标识符，标识**主机/路由器的接口（interface）**。
  - **接口**：主机/路由器与物理信道的连接点。
  - 路由器**通常有多个接口**；主机通常有 1～2 个接口（如有线以太网 + 无线 802.11）。**每个接口关联一个 IP 地址。**
- **地址结构**：
  - **子网部分（subnet part）= 高位 bits**
  - **主机部分（host part）= 低位 bits**
- **什么是子网？** 接口的 IP **子网部分相同**的设备，**不经过中间路由器**就能彼此物理到达。
- **CIDR 记法 `a.b.c.d/x`**：`/x` 表示**前 x 位是子网（网络）前缀**，是这些 IP 的**共同位数**。
  - ⭐ **样题2**：子网 `233.1.1.0/24` 中，这些 IP 的共同位数 = **24 位**。
  - 推论：`/24` → 主机部分 32−24 = 8 位 → 可寻址 2⁸=256 个地址（实际可用主机 254 个，去掉网络号和广播号）。

### 10. DHCP（动态主机配置协议）
新主机入网时，通过 4 步广播自动获取 IP（**DORA**）：
```
1. DHCP Discover —— 主机广播："有 DHCP 服务器吗？"
2. DHCP Offer    —— 服务器广播："给你这个 IP 可以用！"
3. DHCP Request  —— 主机广播："好，我要这个 IP！"
4. DHCP ACK      —— 服务器广播："这个 IP 归你了！"
```
- 全程用**广播（Broadcast）**，因为此时主机还没有 IP。

## 四、重点 / 易考点（MCQ 视角）
- [ ] TCP vs UDP 全维度对比；两者都**不**保证延迟/带宽
- [ ] UDP 分解只看**目的端口**；TCP 分解看 **4 元组**
- [ ] UDP 校验和只**检错不纠错**，16-bit 反码求和
- [ ] 三次握手序列号变化（SYN seq=x → 下一包 x+1）
- [ ] 流量控制靠 **receive_window** 字段，防**接收缓冲区溢出**
- [ ] **转发(本地)** vs **路由(全局)**
- [ ] `/x` 子网 → 共同位=x，主机位=32−x，地址数=2^(32−x)
- [ ] IP 地址标识**接口**，路由器有多个接口
- [ ] IP 分片只在**最终目的地**重组
- [ ] DHCP 用广播

1. 子网 `233.1.1.0/24` 中 IP 的共同位数？
   A. **24 位** ✅　B. 8 位　C. 0　D. 255
2. UDP 多路分解需要什么信息？
   A. **只需目的端口** ✅　B. 源IP+目的IP+源端口+目的端口　C. 源端口+目的端口　D. 只需源端口
3. SYN 包 seq=123，同一发送方随后那个 ACK 包的 seq=？
   A. 123　B. **124** ✅　C. 125　D. 不确定
4. 关于 TCP 和 UDP，下列正确的是？
   A. UDP 提供可靠传输　B. TCP 无连接　C. **两者都不保证带宽** ✅　D. UDP 有流量控制
5. TCP 流量控制使用头部的哪个字段？
   A. checksum　B. sequence number　C. **receive window** ✅　D. TTL
6. 子网 `/26` 可寻址多少个地址？
   A. 26　B. 32　C. **64**（2^(32-26)=2⁶） ✅　D. 256
7. "把分组从输入端口移到输出端口"属于？
   A. **forwarding 转发** ✅　B. routing 路由　C. fragmentation　D. multiplexing

> 💡 **解析**：1-A；2-A（UDP 仅目的端口定位 socket）；3-B（seq+1）；4-C（TCP/UDP 都不保证延迟与带宽）；5-C；6-C（主机位 32−26=6，2⁶=64）；7-A。

## 六、常见易错点
- ❌ UDP 分解写成 4 元组 → UDP **只看目的端口**；4 元组是 **TCP**。
- ❌ 把流量控制和拥塞控制混为一谈 → **流控=保护接收方缓冲区**；**拥塞控制=保护网络**。
- ❌ `/24` 主机数算成 24 → 是 2^(32−24)=256（可用 254）。
- ❌ 以为分片在每跳重组 → **只在最终目的地重组**。
- ❌ 校验和能纠错 → **只能检错**。
