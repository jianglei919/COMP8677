## 二、核心概念详解

### 1. IPv6 报头要点
为应对 IPv4 地址耗尽（IPv6 = **128 位**地址），简化报头，关键新字段：
- **Priority（优先级）**：标识流中数据报的优先级。
- **Flow Label（流标签）**：标识属于**同一条流（flow）**的数据报（"流"的概念定义并不严格）。
- **Next Header（下一个头部）**：标识数据部分对应的**上层协议**（相当于 IPv4 的 protocol 字段）。

### 2. 路由协议（Routing Protocol）目标
- **目标**：确定从发送主机到接收主机、**穿过路由器网络**的**路径（routes）**。
- 路径的"好"可以按不同标准：**最低代价（least cost）/ 最快（fastest）/ 最不拥塞（least congested）**。

### 3. 链路层在哪里实现
- 在**每台主机**中，链路层实现于**适配器（adapter）**，即**网络接口卡 NIC（Network Interface Card）**，或集成在芯片里。
- 例：以太网卡、802.11 卡、以太网芯片组——实现**链路层 + 物理层**。

### 4. 链路类型
| 类型 | 说明 | 例子 |
|---|---|---|
| **点到点 point-to-point** | 一个发送方、一个接收方 | PPP 拨号接入；以太网交换机↔主机 |
| **广播 broadcast（共享介质）** | 多节点共享同一线缆/介质 | 老式（总线）以太网、上行 HFC、**802.11 无线 LAN** |

### 5. MAC 地址（链路层地址）
- 又称 LAN 地址 / 物理地址；用于在**同一子网内**把帧从一个接口送到另一个接口。
- **长度 48 位**，用**十六进制（base 16）**表示，**每个十六进制数字代表 4 比特**（如 `08:00:27:db:4e:fc`）。
- 对比：**MAC 地址固化在网卡（与硬件绑定）；IP 地址随网络位置变化**。

### 6. ARP（Address Resolution Protocol）★考点★
- **作用**：在**同一子网内**，由目标的 **IP 地址**解析出其 **MAC 地址**。
- **plug-and-play（即插即用）**：节点**自动**建立 ARP 表，**无需网管干预**。
- 工作方式：源在子网内**广播 ARP 查询**"谁的 IP 是 X？"，拥有该 IP 的节点**单播**回复自己的 MAC；结果缓存在 ARP 表（有 TTL）。

### 7. 以太网交换机（Switch）：自学习 + 转发/泛洪 ★高频考点★
- **特点**：主机与交换机**专线直连**；`A↔A'` 和 `B↔B'` 可**同时传输、无冲突**（因为没有共享的源/目的，交换机可同时投递）。
- **自学习（self-learning）**：交换机通过收到帧的**源 MAC + 进入接口**，自动建立"**MAC ↔ 接口**"转发表（switch forwarding table）。
  - 例："交换机怎么知道 A 经接口 4 可达？"——因为之前收到过 A 发出的、从接口 4 进来的帧。
- **转发表查找规则**（收到目的 MAC 为 D 的帧时）：
  | 情况 | 动作 |
  |---|---|
  | 表中**无** D 的记录 | ⭐ **泛洪（flood）**：向**除入口外的所有接口**转发 |
  | 表中有 D，且对应**入口接口** | **丢弃**（filter，目的就在来的那一侧） |
  | 表中有 D，对应**其他接口** | **定向转发**到那个接口 |
  - ⭐ **样题6**：交换机收到目的 MAC 不在转发表中的帧 → **泛洪到除入口外的所有接口**（flood to all interfaces except the incoming one）。
- ⚠️ 注意：交换机**不**用 ARP 找接口；它靠**自学习**。（"用 ARP 找接口"是干扰项。）

### 8. 跨子网通信：MAC 逐跳变化（A 经路由器 R 发往 B）★难点★
关键口诀：**IP 地址端到端不变；MAC 地址逐跳（neighboring）变化。**
- 走查（walkthrough）：A 把数据报发给 B，途经路由器 R。同时关注 **IP 层（数据报）地址**和 **MAC 层（帧）地址**。
- 前提：A 知道 **B 的 IP**、知道**第一跳路由器 R 的 IP**、并通过 ARP 知道 **R 的 MAC**。
- **A → R 这一跳的帧**：
  - 源 IP = A，目的 IP = **B**（IP 端到端不变！）
  - 源 MAC = A，目的 MAC = **R 的 MAC**（指向下一跳邻居）
- 到 R 后，R 去掉旧帧头，查路由，重新封装：
- **R → B 这一跳的帧**：
  - 源 IP = A，目的 IP = B（仍不变）
  - 源 MAC = **R**，目的 MAC = **B 的 MAC**
- 💡 一句话：**相邻通信用相邻设备的 MAC 地址**；每过一个路由器，帧的源/目的 MAC 都换成"本跳两端"的 MAC，而 IP 始终是最终的源和目的。

## 三、重点 / 易考点（MCQ 视角）
- [ ] 交换机收到未知目的 MAC → **泛洪（除入口外所有口）**
- [ ] 交换机**自学习**（靠源MAC+入口），不是用 ARP
- [ ] ARP = 同子网内 **IP→MAC**，即插即用
- [ ] MAC 48 位、十六进制、每位=4 bit；固化在网卡
- [ ] 链路层实现在 **NIC/适配器**
- [ ] 点到点 vs 广播链路的例子
- [ ] 跨子网：**IP 不变，MAC 逐跳变**
- [ ] IPv6 三字段：priority / flow label / next header；地址 128 位

## 四、自测题（MCQ 仿真）
1. 交换机收到目的 MAC 不在转发表中的帧，会怎样？
   A. 丢弃　B. 转发到默认接口　C. **泛洪到除入口外所有接口** ✅　D. 用 ARP 查接口
2. ARP 用来解析？
   A. 主机名→IP　B. **IP→MAC** ✅　C. MAC→IP　D. IP→端口
3. MAC 地址长度是？
   A. 32 位　B. **48 位** ✅　C. 64 位　D. 128 位
4. 数据报 A→B 经路由器 R，A→R 这一跳帧的目的 MAC 是？
   A. B 的 MAC　B. **R 的 MAC** ✅　C. A 的 MAC　D. 广播地址
5. 链路层主要实现在？
   A. CPU　B. **网卡/适配器(NIC)** ✅　C. 路由表　D. DNS 服务器
6. 跨多个路由器传输时，端到端保持不变的是？
   A. 目的 MAC　B. 源 MAC　C. **源/目的 IP** ✅　D. TTL
7. 交换机如何建立转发表？
   A. 用 ARP　B. 管理员手动配置　C. **自学习（源MAC+入口）** ✅　D. DHCP

> 💡 **解析**：1-C；2-B；3-B；4-B（下一跳邻居的 MAC）；5-B；6-C（IP 端到端不变，MAC 逐跳变）；7-C。

## 五、常见易错点
- ❌ "交换机用 ARP 找接口" → 错，交换机靠**自学习**；**ARP 是主机用来 IP→MAC**。
- ❌ 跨子网时以为目的 MAC 一直是 B → 第一跳目的 MAC 是 **路由器 R**。
- ❌ 把 MAC（48位）和 IP（32位）位数搞混。
- ❌ 泛洪时把入口也算进去 → 是**除入口外**的所有接口。
