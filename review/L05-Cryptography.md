## 二、核心概念详解

### 1. 单向哈希函数（One-way Hash Function）★
- **定义**：把**长**输入映射为**短**输出（如 128-bit 摘要），并保持安全性。
- **两大性质（必背）**：
  1. **单向性（One-way / 抗原像）**：已知 `hash(m)=h`，**难以反推 m**。
  2. **抗碰撞（Collision resistant）**：**难以找到 m1≠m2 使 hash(m1)=hash(m2)**。
- **常见家族与现状**：
  | 家族 | 由来 | 状态 |
  |---|---|---|
  | **MD**（Message Digest，Ron Rivest） | MD2/MD4/MD5/MD6 | MD2/MD4 **严重破解(废弃)**；**MD5 抗碰撞被破**(单向性未破)；MD6 应 NIST 提案而生 |
  | **SHA**（NIST 发布） | SHA-0/1/2/3 | SHA-0 因缺陷撤回；**SHA-1 2017 年发现碰撞攻击**；**SHA-2(含 SHA-256/512) 暂无重大攻击**；SHA-3 2015 发布，**构造结构不同** |
- 👉 实践用 **SHA-256/512**，避免 MD5/SHA-1 做安全用途。

### 2. 哈希命令与编程
- Linux：`md5sum`、`sha224sum`、`sha256sum`、`sha384sum`、`sha512sum`。
- Python 用 **PyCryptodome** 包（初始化 hash 对象 → update → 取摘要）。

### 3. 口令验证（Password Verification）
- 登录要提供口令，但**不能明文存储**口令。
- Linux 把**加盐哈希后的口令**存于 **`/etc/shadow`**。
- 验证：你输入口令 → 系统**哈希**后与存储比对是否一致。
- **shadow 口令字段 3 部分**：`$算法$salt$口令哈希`（salt 和哈希编码成可打印字符）。
  - **盐（salt）作用**：让相同口令哈希结果不同，**抵御彩虹表 / 预计算攻击**。

### 4. 公钥密码系统概述
- **私钥（对称）密码**：加解密**共用同一密钥**。
- **1976 Diffie & Hellman**：提出**公钥加密**概念。
- **1978 Rivest, Shamir, Adleman**：**RSA** 公钥加密。

### 5. 模运算（Modulo）
- `a mod n` = a 除以 n 的**余数**；n 称**模数（modulus）**。例：`10 mod 3 = 1`，`15 mod 5 = 0`。
- **关键性质**：`+`、`*`、**乘幂**在 mod n 下，可以**中途先取模**再算，结果不变（便于手算大数幂）。
  - 例：`2⁸ mod 12 = (2⁴·2⁴) mod 12 = (4·4) mod 12 = 4`。

### 6. RSA 密码系统 ★★（最重要）
**(a) 密钥生成**
1. 选两个大素数 `p, q`；
2. `n = p·q`（模数）；
3. 选**奇数** `e`，`1 < e < n`，常取 **e = 65537**（且 e 与 (p−1)(q−1) 互素）；
4. 求 `d`，使 `e·d mod (p−1)(q−1) = 1`（用**扩展欧几里得算法**，即 `d = inv(e, (p−1)(q−1))`）；
   - 等价：`e·d = k·(p−1)(q−1) + 1`（某整数 k）。
5. **公钥 = (e, n)**；**私钥 = d**。

**(b) 加密 / 解密**（明文当成数字，要求 M < n）
- 加密：`C = Mᵉ mod n`
- 解密：`M = Cᵈ mod n`

**(c) 小数手算例（必练）**
```
p=13, q=17  →  n=221,  (p−1)(q−1)=12·16=192
选 e=7      →  求 d: 7d ≡ 1 (mod 192) → d=55
加密 M=36:  C = 36⁷ mod 221 = 179      （python: pow(36,7,221)）
解密 C=179: M = 179⁵⁵ mod 221 = 36     （python: pow(179,55,221)）
```
- 💡 安全基于**大整数分解难题**：由公开的 n 很难分解出 p、q。

### 7. OpenSSL 生成 RSA 密钥
```bash
openssl genrsa -aes128 -out private.pem 1024     # 生成1024位密钥对(私钥用AES128加密保护)
openssl rsa -in private.pem -pubout > public.pem  # 从私钥导出公钥
```
- `private.pem` 是 DER 二进制的 **Base64 编码**。

### 8. 数字签名（Digital Signature）★
- **目标**：通过签名**证明真实性/认证**——**用私钥签**，**人人可用公钥验**。
- **朴素 RSA 签名**：`s = mᵈ mod n`；验证 `sᵉ = m mod n ?`
  - 正确性：`sᵉ = mᵈᵉ = m mod n`（就是 RSA 解密的逆）。
  - ⚠️ **问题**：`m` 与 `m+n` 签名相同（可被伪造/数学性质攻击），不安全！
- **实际签名（先哈希）**：`s = H(m)ᵈ mod n`；验证 `sᵉ = H(m) mod n ?`
  - `H` 可为 **MD5 / SHA-256 / SHA-512**。
  - 好处：消息任意长 → 定长摘要；消除上面的代数弱点。
- **Python**：用 **PSS** 方案（`sign_RSA.py` / `verify_RSA.py`）。
- ⚠️ **区分**：**加密用接收方公钥（私钥解密）**；**签名用发送方私钥（公钥验证）**——方向相反！

### 9. 应用：信用卡认证
- 信用卡公司需确认交易真实 → 交易由卡用**私钥签名**。
- 验证签名 → 对发卡行：卡主已批准交易；对诚实商家：可保存交易、事后提交给信用卡公司。

### 10. 混合加密（Hybrid Encryption）★
- **动机**：公钥加密**计算开销大**。
- **做法**：用**公钥算法只交换一个对称的"会话密钥（session key）"**；再用**对称算法（AES）**加密真正的数据。
  - 例：`K^e mod n`（用 RSA 传 K）+ `AES_k(b'This is my secret')`。
- 💡 TLS 等都用这个思路（公钥定密钥，对称传数据）。

### 11. AES（高级加密标准）★
- AES 是**块加密（block cipher）**。
- **块大小固定 128 位**：128-bit 明文 → 128-bit 密文。
- **三种密钥长度**：**128 / 192 / 256 位**。

### 12. 加密模式：ECB vs CBC + 填充 ★高频★
- **ECB（电子密码本 Electronic Codebook）**：每块**独立**用同一密钥加密。
  - ❌ **致命缺陷**：相同明文块 → 相同密文块，**泄露数据模式**（经典"加密企鹅图仍能看出轮廓"）。**不适合文件加密。**
- **CBC（密码块链接 Cipher Block Chaining）**：
  - 每块加密前先与**前一块密文异或**；第一块与 **IV（初始化向量）** 异或。
  - **不同 IV → 同一明文文件加密出完全不同的密文**；前面的块影响后面的密文 → **避免了 ECB 的模式泄露问题**。
- **填充（Padding）**：
  - 加密按块进行（AES-128 块=128 位=16 字节）。
  - 若明文不足整块（如 120 位），需**填充**补齐成整块。
  - ⚠️ **不能简单补 0**：否则接收方分不清原文是 `M` 还是 `M0`、`M00`…（无法确定填充长度）。→ 用 **PKCS#5/#7** 等可逆填充。

### 13. Diffie-Hellman 密钥交换（DH）★
- **目标**：Alice 与 Bob 在公开信道上**协商出共享密钥 K**。
- **公开参数**：大素数 `p`，底数 `g < p`（如 g=2）。
- **过程**：
  ```
  Alice 选私密 x → 发送 g^x mod p
  Bob   选私密 y → 发送 g^y mod p
  Alice 算: sk = (g^y)^x mod p = g^(xy) mod p
  Bob   算: sk = (g^x)^y mod p = g^(xy) mod p   ← 两者相同
  ```
- **安全基础**：**离散对数假设（Discrete Log）**——由 `g^x mod p` **难以反推 x**。
- ⚠️ 原始 DH **不防中间人（MITM）**，需结合认证（见 [[L06-PKI-TLS]]）。

## 三、重点回顾
- [ ] 哈希两性质：**单向 + 抗碰撞**；MD5/SHA-1 抗碰撞已破，用 **SHA-256**
- [ ] 口令存 **/etc/shadow**，加 **salt** 防彩虹表
- [ ] **RSA**：`n=pq`，`d=inv(e,(p−1)(q−1))`，**加密 C=Mᵉ、解密 M=Cᵈ**
- [ ] **签名 s=H(m)ᵈ**，验证 sᵉ=H(m)；为何要先哈希
- [ ] 加密=公钥；签名=私钥（方向相反）
- [ ] 混合加密：公钥送会话密钥 + AES 传数据
- [ ] AES：块 128 位，密钥 128/192/256
- [ ] **ECB 泄露模式 → 用 CBC（IV+链接）**；为何不能补 0 填充
- [ ] **DH**：共享 `g^(xy) mod p`，安全基于离散对数

## 四、自测题
1. 哈希函数的两个核心安全性质？→ **单向性**、**抗碰撞性**。
2. RSA 中 p=13,q=17,e=7，求 d？→ φ=192，`d=inv(7,192)=55`。
3. RSA 加密公式？解密公式？→ `C=Mᵉ mod n`；`M=Cᵈ mod n`。
4. 数字签名为什么要对 H(m) 而不是 m 签名？→ 支持任意长消息 + **消除 `m` 与 `m+n` 同签名的弱点**。
5. ECB 模式的主要缺陷？→ 相同明文块→相同密文块，**泄露数据模式**。
6. CBC 靠什么避免该缺陷？→ **IV + 与前块密文异或链接**。
7. 为什么填充不能简单补 0？→ 接收方**无法确定**原文与填充边界（M 还是 M0、M00…）。
8. DH 中双方最终共享的密钥是？→ `g^(xy) mod p`；安全基于**离散对数难题**。

## 五、常见易错点
- ❌ **加密/签名密钥用反**：加密用**接收方公钥**；签名用**发送方私钥**。
- ❌ 以为 MD5 完全可用 → 抗碰撞**已破**，仅勿用于安全场景。
- ❌ 把 AES 当公钥算法 → AES 是**对称块加密**。
- ❌ ECB 用于文件加密 → 会泄露模式，应用 **CBC**。
- ❌ 以为 DH 直接安全 → **不防中间人**，需认证。
