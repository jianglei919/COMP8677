## 1️⃣ 五层协议栈（必背）
| 层 | 功能 | 协议 | **PDU** |
|---|---|---|---|
| 应用 Application | 网络应用 | HTTP, FTP, SMTP, DNS | message 报文 |
| 传输 Transport | 进程↔进程 | **TCP, UDP** | segment 段 |
| 网络 Network | 主机↔主机路由 | **IP**, 路由协议 | datagram 数据报 |
| 链路 Link | 相邻结点 | Ethernet, 802.11, PPP | **frame 帧** |
| 物理 Physical | 比特 | — | bit |
口诀 **应-传-网-链-物**。PDU：**报文→段→数据报→帧→比特**。

## 2️⃣ 2 的幂（子网心算用）
| n | 2ⁿ | n | 2ⁿ |
|---|---|---|---|
| 1 | 2 | 6 | 64 |
| 2 | 4 | 7 | 128 |
| 3 | 8 | 8 | 256 |
| 4 | 16 | 9 | 512 |
| 5 | 32 | 10 | 1024 |

**子网 `a.b.c.d/x`**：
- 共同(网络前缀)位 = **x**
- 主机位 = **32 − x**
- 地址总数 = **2^(32−x)**；可用主机 = 2^(32−x) − 2（去网络号+广播号）
- 例：`/24`→共同24、主机8、256个；`/26`→主机6、**64**个；`/30`→主机2、4个(可用2)。

## 3️⃣ TCP vs UDP
| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接(3次握手) | 无连接 |
| 可靠 | 可靠按序字节流 | 不可靠/可能乱序 |
| 边界 | 无报文边界 | 保留边界 |
| 流控/拥塞 | ✅/✅ | ❌/❌ |
| **分解依据** | **4元组**(srcIP,srcPort,dstIP,dstPort) | **仅目的端口** |
两者都**不**保证：**延迟、带宽**。

---

## 4️⃣ 必记数字 / 字段
- IP = **32 位**；MAC = **48 位**(十六进制,每位4bit)；IPv6 = 128 位
- UDP 校验和：16-bit 反码求和，**只检错不纠错**
- 流量控制字段：**receive window**（防接收缓冲区溢出）
- TCP 握手：SYN seq=x → SYN+ACK(seq=y,ack=x+1) → ACK(**seq=x+1**,ack=y+1)；**SYN/FIN 各占 1 序号**
- HTTP=应用层/TCP/端口80；DNS=名字↔IP，从 **ROOT** 解析

---

## 5️⃣ 网络层 / 链路层动作
- **转发 forwarding** = 路由器内 输入口→输出口（本地）
- **路由 routing** = 选源到目的路径（全局）
- **IP 分片**：超 MTU 才分片，**只在最终目的重组**
- **交换机收到帧，按目的 MAC 查表**：
  - 表中无 → **泛洪(除入口外所有口)** ⭐
  - 表中有=入口 → 丢弃；表中有≠入口 → 定向转发
  - 建表靠**自学习(源MAC+入口)**，**不是 ARP**
- **ARP** = 主机在**同子网** IP→MAC，即插即用
- **跨子网**：**IP 端到端不变，MAC 逐跳变**（A→R 帧目的MAC=R；R→B 帧目的MAC=B）
- **DHCP** 用广播获取 IP（Discover→Offer→Request→ACK）

## 6️⃣ 官方样题闪卡（背答案+理由）
1. 无线 AP 作用 → **提供无线链路**
2. `233.1.1.0/24` 共同位 → **24**
3. 链路层分组 → **frame**
4. UDP 分解需要 → **只需目的端口**
5. SYN seq=123 → 下一包 → **124**（seq+1）
6. 交换机未知目的 MAC → **泛洪(除入口外所有口)**

---

## ⚠️ 最易错 6 连
1. segment/datagram/frame 对应层弄反 → **传输/网络/链路**
2. UDP 分解写成 4 元组 → UDP **只看目的端口**
3. `/24` 主机数写 24 → **256**(=2⁸)
4. "交换机用 ARP 找口" → 错，**自学习**
5. 流控 vs 拥塞控制混 → 流控**护接收方**，拥塞控制**护网络**
6. 跨子网目的 MAC 一直是 B → 第一跳是**路由器 R**
